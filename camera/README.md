# Front camera (Samsung S5KC505A)

The ThinkSmart View's 5 MP front camera, working on the mainline-based 6.19 kernel. Applications
see it as an ordinary webcam, `/dev/video10` ("ThinkSmart_Camera", 1280×720 YUYV, 30 fps); libcamera
applications (`cam`) can use it directly, up to 2600×1960.

```
S5KC505A ──CSI-2, 2 lanes──▶ CSIPHY0 ▶ CSID0 ▶ ISPIF ▶ VFE0 RDI (qcom-camss, RAW10)
                                                         │
                     libcamera 0.8 simple pipeline + GPU software ISP (AE, AWB, CCM, demosaic)
                                                         │
                     tscam-bridge ──YUYV──▶ v4l2loopback /dev/video10 ──▶ any V4L2 application
```

## What is here

| Path | What | Built by |
| --- | --- | --- |
| `s5kc505a/` | V4L2 sensor driver (GPL-2.0). Register tables in `s5kc505a_regs.h` are generated by `tools/extract-vendor-data.py` | `build.sh` |
| `apq8053-lenovo-cd-18781y-camera.dtsi` | camss, CCI, the sensor node and its supplies, appended to the stock DTS | `build.sh` |
| (pinned upstream) | v4l2loopback v0.15.4 | `build.sh` |
| `libcamera-s5kc505a.patch` | sensor helper (gain model, black level) and properties for libcamera v0.8.0 | `build-libcamera.sh` |
| `s5kc505a.yaml` | software ISP tuning: vendor colour matrix, AE target | `build-libcamera.sh` |
| `tscam-bridge.cpp` | libcamera → v4l2loopback webcam bridge, camera on only while an application reads | `build-libcamera.sh` |
| `thinksmart-camera.service`, `70-libcamera-dmabuf.rules`, `v4l2loopback-*.conf` | system files | — |

`build.sh` writes `out/s5kc505a.ko`, `out/v4l2loopback.ko` and `out/apq8053-lenovo-cd-18781y.dtb`
(checked against `expected.md5`); `build-libcamera.sh` writes `out/thinksmart-camera_*_arm64.deb`.
`image/device-setup.sh camera` installs all of it on a device; `image/build-image.sh` checks it is
in a capture before making an image.

The DTB from `build.sh` is the stock one **plus the DMIC fix** (`../codec-dmic`) plus the camera
nodes, so it replaces the codec-dmic DTB: run `device-setup.sh camera` after `device-setup.sh codec`.

## Building

```sh
kernel/build.sh                 # once: the kernel tree in the kbuild-src volume (see kernel/README.md)
camera/build.sh                 # modules + DTB, in kbuild:clang21
camera/build-libcamera.sh       # libcamera + bridge .deb, in ubuntu:24.04 arm64 (colima on a Mac)
# copy the repository to the device, then on the device:
sudo sh image/device-setup.sh camera     # writes /boot: ask the owner first; reboot afterwards
```

libcamera is not built on the device: its `-dev` packages conflict with this image's patched Mesa
and KDE neon packages. The package installs under `/usr/local` and only needs runtime libraries.

## Hardware

Taken from the stock Android firmware (device tree, `camera_config.xml`, `libmmcamera_s5kc505a.so`)
and confirmed on the device:

| | |
| --- | --- |
| Sensor | Samsung S5KC505A, 2608×1960 RAW10, chip id `0x5034` at register `0x0000` |
| Control | CCI master 0, I2C address `0x37`, 16-bit register addresses, 400 kHz |
| Data | CSIPHY0 / CSID0, 2 data lanes (`clock-lanes = <7>; data-lanes = <0 1>`), 960 Mbit/s per lane |
| Clock | MCLK0 on gpio26, 24 MHz |
| Control lines | RESET gpio40, STANDBY gpio39 (both active low) |
| Supplies | VIO = PM8953 L6 1.8 V; DVDD = L2 1.2 V switched by gpio118; AVDD = L17 2.85 V switched by gpio119 |
| Power-up | AVDD, DVDD, VIO, MCLK, 1 ms, RESET release, 10 ms, STANDBY release, 10 ms |
| Mounting | upside down: `rotation = <180>` (libcamera flips it); colour order GRBG unflipped, both flips shift it |

Modes (vendor register sets; the driver defaults every mode to 30 fps, the vendor maximum is
reachable through the `vertical_blanking` control):

| Output | Crop | Max fps |
| --- | --- | --- |
| 2608×1960 | full | 30 |
| 1936×1096 | centre | 60 |
| 1304×980 | full, 2×2 binned | 30 |
| 1296×736 | 2592×1472, binned | 85 |
| 640×490 | full height, 4×4 binned | 120 |

Exposure is register `0x0202` (lines, frame length − 8 at most), analogue gain `0x0204`
(`0x20` = 1×, linear, up to ~16×), frame length `0x0340`, flips `0x0101`, test pattern `0x0600`.
Note the sensor's colour-bar test pattern is generated after the flip logic, so it cannot be used
to find the colour order; that came from real images (the two green planes correlate best).

## Reproducing the vendor data

`tools/extract-vendor-data.py` reads the stock sensor and chromatix libraries from your own eMMC
backup and regenerates `s5kc505a/s5kc505a_regs.h`, printing the I2C address, chip id, power
sequence and the vendor colour matrices (see the script's header for the `dd`/`debugfs` steps).
No file from the stock firmware is part of this repository.

## On the device

```sh
cam -l                                          # the camera, as libcamera sees it
cam -c1 -C30 -s width=2600,height=1960,pixelformat=BGR888 --file='photo-#.ppm'
journalctl -u thinksmart-camera -f              # bridge: clients, camera start/stop, fps
sudo systemctl disable --now thinksmart-camera  # no /dev/video10
```

The bridge resolution is the `-s` option in `thinksmart-camera.service` (sizes: `cam -c1 -s
role=viewfinder -I`); `-a` keeps the camera running instead of starting it on demand.

## Known limits

- One vendor colour matrix is used for every light (the library does not label which illuminant
  each of its matrices is for); there is no per-illuminant interpolation and no lens-shading
  correction.
- Opening `/dev/video10` takes 1–2 s to the first frame (the camera starts on demand).
- The software ISP uses the GPU; with the bridge streaming 720p the bridge takes about 70 % of
  one core.
